# CarKeeper

CarKeeper - Telegram-приложение для учета расходов автомобиля, пробега, топлива и обслуживания.

## Быстрый старт

Минимальные требования:

- Node.js 20 или новее;
- npm;
- PostgreSQL;
- Telegram-бот, созданный через `@BotFather`.

Установка зависимостей и подготовка `.env`:

```bash
npm install
cp .env.example .env
```

Заполни `.env`:

```env
TELEGRAM_BOT_TOKEN=TOKEN_FROM_BOTFATHER
DATABASE_URL=postgres://USER:PASSWORD@localhost:5432/car_ceeper
DEFAULT_CURRENCY=BYN
NODE_ENV=development
BOT_MODE=polling
PORT=3000
REMINDER_CHECK_INTERVAL_MINUTES=1440
WEBHOOK_URL=
WEBHOOK_SECRET=
```

Создай PostgreSQL-базу `car_ceeper`. Это можно сделать через Navicat или командой:

```bash
createdb car_ceeper
```

Проверь подключение и примени миграции:

```bash
npm run db:check
npm run migrate:up
npm run migrate:status
```

Проверь конфигурацию и запусти бота:

```bash
npm run config:check
npm run dev
```

Локально бот работает через long polling. Запускай только один экземпляр `npm run dev` для одного Telegram-бота, иначе Telegram вернет `409 Conflict`.

Healthcheck endpoint доступен на:

```text
GET http://localhost:3000/health
```

Ответ:

```json
{"status":"ok"}
```

## Отчеты и экспорт

Команда `/report month` показывает полный отчет за текущий месяц: сумму, категории, стоимость владения, стоимость 1 км при наличии данных, топ расходов и динамику по неделям.

Команда `/report year` показывает годовой отчет: сумму, категории, стоимость владения, стоимость 1 км при наличии данных, динамику по месяцам, самый дорогой месяц и топ расходов.

Для отчетов доступны периоды:

```text
/report month
/report year
/report 2026-05
/report 2026
```

Команда `/export` отправляет CSV-файл с расходами за текущий месяц. Также поддерживаются периоды:

```text
/export month
/export year
/export 2026-05
/export 2026
/export csv 2026-05
```

Excel-экспорт доступен через параметр формата:

```text
/export excel
/export xlsx
/export excel 2026-05
/export xlsx 2026
```

Excel-файл содержит листы `Расходы`, `Категории` и `Динамика`. CSV остается форматом по умолчанию.

Если расходов за выбранный период нет, бот не отправляет пустой файл и отвечает сообщением. Если для стоимости 1 км не хватает данных, отчет остается доступным и показывает подсказку добавить минимум две заправки с пробегом.

## Схема данных

- `users` - Telegram-пользователи, `telegram_id` уникален;
- `cars` - автомобили пользователя, один активный автомобиль на пользователя ограничен индексом `cars_one_active_car_per_user_idx`, текущий пробег хранится в `current_mileage`;
- `expenses` - расходы пользователя, сумма должна быть больше нуля, категория хранится техническим enum-ключом;
- `fuel_entries` - заправки пользователя: литры, сумма, цена за литр, пробег и ссылка на расход в `expenses`;
- `service_entries` - события обслуживания: тип работы, сумма, пробег, интервалы следующей замены и ссылка на расход в `expenses`;
- `reminders` - напоминания пользователя по дате, пробегу или сервисному событию со статусами `active`, `completed`, `dismissed`; выполненные напоминания не удаляются и остаются доступными для будущих отчетов;
- `updated_at` обновляется автоматически через PostgreSQL trigger.

Команда `/fuel` создает две связанные записи: заправку в `fuel_entries` и обычный расход категории `fuel` в `expenses`. Поэтому топливо видно в `/history`, `/today`, `/stats` и `/month`.

Команда `/service` создает две связанные записи: событие обслуживания в `service_entries` и обычный расход категории `maintenance` в `expenses`. Поэтому ТО и расходники видны в `/history`, `/today`, `/stats` и `/month`.

Если у `/service` есть следующий пробег или следующая дата, бот автоматически создает связанную задачу в `reminders`. Ручные напоминания добавляются через `/remind`, ближайшие задачи видны в `/todo`, закрываются через `/done 12`.

Фоновая проверка напоминаний запускается при старте polling-бота и затем по интервалу `REMINDER_CHECK_INTERVAL_MINUTES`. Telegram-уведомление отправляется только для наступивших active reminders, а `last_notified_at` обновляется только после успешной отправки.

## Подготовка к деплою

Production-запуск использует стандартные команды:

```bash
npm run build
npm run start
```

Переменные окружения для production:

```env
TELEGRAM_BOT_TOKEN=
DATABASE_URL=
DEFAULT_CURRENCY=BYN
NODE_ENV=production
BOT_MODE=polling
PORT=3000
REMINDER_CHECK_INTERVAL_MINUTES=1440
WEBHOOK_URL=
WEBHOOK_SECRET=
```

`DATABASE_URL` использует обычный PostgreSQL connection string, поэтому подходит для локальной PostgreSQL, Supabase, Railway, Render PostgreSQL и других managed PostgreSQL-провайдеров.

Сейчас поддерживается `BOT_MODE=polling`. Значение `BOT_MODE=webhook` зарезервировано для будущего production-webhook режима и пока завершит запуск понятной ошибкой. Для webhook позже понадобятся `WEBHOOK_URL`, `WEBHOOK_SECRET` и HTTP endpoint для Telegram updates.

Для Render, Railway, Fly.io или VPS важно:

- не коммитить `.env`;
- задать env vars в настройках платформы;
- использовать `npm run build` перед запуском;
- запускать `npm run start`;
- открыть `GET /health` как healthcheck;
- держать только один активный экземпляр polling-бота.

## Этап 1. Базовый учет расходов

Первый этап нужен, чтобы получить минимально полезную версию приложения: пользователь может быстро записывать расходы по автомобилю, смотреть историю и понимать, сколько денег ушло за выбранный период.

На этом этапе не нужно делать учет топлива, расходники, напоминания и сложные отчеты. Главное - создать надежную основу: бот, категории расходов, хранение данных и простую статистику.

## Цель этапа

Сделать Telegram-бота, который позволяет:

- добавить автомобиль;
- записать расход;
- выбрать или автоматически определить категорию расхода;
- посмотреть последние расходы;
- посмотреть сумму расходов за месяц;
- посмотреть расходы по категориям;
- удалить ошибочно добавленную запись.

## Что должно получиться в конце этапа

Пользователь открывает Telegram, пишет боту короткое сообщение или команду, а бот сохраняет расход и показывает понятный ответ.

Пример:

```text
/add бензин 3200
```

Ответ бота:

```text
Расход добавлен:
Категория: топливо
Сумма: 3200
Комментарий: бензин
Дата: 14.05.2026
```

После этого пользователь может открыть статистику:

```text
/stats
```

И получить:

```text
Расходы за май 2026:
Всего: 12800

По категориям:
Топливо: 9000
Мойка: 800
Ремонт: 3000
```

## Основные сценарии пользователя

### 1. Первый запуск

Пользователь запускает бота командой:

```text
/start
```

Бот объясняет, что умеет, и предлагает добавить автомобиль.

Минимальные данные автомобиля:

- название;
- марка;
- модель;
- год выпуска, необязательно;
- текущий пробег, необязательно на первом этапе.

Пример:

```text
/car Toyota Camry
```

Ответ:

```text
Автомобиль добавлен: Toyota Camry
Теперь можно записывать расходы через /add.
```

### 2. Добавление расхода

Пользователь может добавить расход командой:

```text
/add мойка 800
```

Или более подробно:

```text
/add ремонт 4500 замена лампы
```

Минимальные поля расхода:

- сумма;
- категория;
- дата;
- комментарий;
- автомобиль;
- пользователь Telegram.

Если дата не указана, используется текущая дата.

### 3. Просмотр истории

Команда:

```text
/history
```

Показывает последние 10 расходов.

Пример ответа:

```text
Последние расходы:
1. 14.05.2026 - топливо - 3200 - бензин
2. 13.05.2026 - мойка - 800 - мойка кузова
3. 10.05.2026 - ремонт - 4500 - замена лампы
```

### 4. Простая статистика

Команда:

```text
/stats
```

Показывает расходы за текущий месяц:

- общая сумма;
- сумма по категориям;
- количество записей;
- самый крупный расход.

### 5. Удаление последней ошибочной записи

Команда:

```text
/undo
```

Удаляет последний добавленный расход пользователя.

Это важно для удобства, потому что на первом этапе пользователь часто будет ошибаться при вводе.

## Категории расходов

На первом этапе достаточно фиксированного списка:

- топливо;
- мойка;
- ремонт;
- ТО;
- страховка;
- парковка;
- штрафы;
- запчасти;
- налог;
- прочее.

Можно поддержать простые синонимы:

```text
бензин -> топливо
дизель -> топливо
заправка -> топливо
автомойка -> мойка
осаго -> страховка
каско -> страховка
сервис -> ТО
```

Если категория не распознана, расход попадает в категорию `прочее`.

## Команды первого этапа

Обязательные команды:

```text
/start
/help
/car
/add
/history
/stats
/undo
```

Желательные команды:

```text
/categories
/month
/today
```

Описание:

- `/start` - первый запуск и краткое описание бота;
- `/help` - список команд и примеры ввода;
- `/car` - добавить или изменить автомобиль;
- `/add` - добавить расход;
- `/history` - показать последние расходы;
- `/stats` - показать статистику за текущий месяц;
- `/undo` - удалить последний добавленный расход;
- `/categories` - показать список категорий;
- `/month` - показать расходы за текущий месяц;
- `/today` - показать расходы за сегодня.

## Форматы ввода

Минимально нужно поддержать такие варианты:

```text
/add бензин 3200
/add мойка 800
/add ремонт 4500 замена лампы
/add страховка 28000 ОСАГО
```

На первом этапе не нужно делать сложный AI-парсер. Достаточно простого правила:

1. Найти сумму в сообщении.
2. Найти категорию или синоним категории.
3. Остальной текст сохранить как комментарий.
4. Если категория не найдена, поставить `прочее`.

## Технический минимум

Для первого этапа достаточно:

- Telegram Bot API;
- backend-приложение;
- база данных;
- локальный запуск;
- файл с переменными окружения;
- базовая обработка ошибок.

Рекомендуемый простой стек:

- Node.js;
- JavaScript или TypeScript;
- PostgreSQL с первого этапа;
- локальная PostgreSQL-база для разработки;
- Supabase или другой managed PostgreSQL для хостинга;
- long polling для локальной разработки;
- webhook для хостинга.

Почему PostgreSQL сразу:

- не нужно будет переносить данные с SQLite на PostgreSQL перед деплоем;
- локальная и продакшен-база будут работать одинаково;
- проще заранее заложить нормальную структуру таблиц, индексы и связи;
- в будущем будет проще добавить несколько автомобилей, отчеты, напоминания и экспорт.

## Переменные окружения

Нужны минимум:

```text
TELEGRAM_BOT_TOKEN=
DATABASE_URL=postgresql://user:password@localhost:5432/car_expenses
DEFAULT_CURRENCY=BYN
```

Токен создается через Telegram-бота `@BotFather`.

Для локальной разработки можно поднять PostgreSQL на компьютере или через Docker. Для бесплатного хостинга удобный вариант - Supabase Free, потому что он сразу дает готовый PostgreSQL и строку подключения `DATABASE_URL`.

## Что не делаем в первом этапе

Чтобы не растягивать MVP, в первый этап не входят:

- расчет расхода топлива;
- учет литров;
- пробег;
- расходники;
- напоминания;
- фото чеков;
- распознавание чеков;
- графики;
- несколько автомобилей;
- семейный доступ;
- AI-обработка свободного текста;
- экспорт в Excel.

Эти функции лучше добавлять после того, как базовый учет расходов уже работает.

## Критерии готовности

Этап можно считать готовым, если:

- бот запускается локально;
- пользователь может добавить автомобиль;
- пользователь может добавить расход;
- расход сохраняется в базе;
- `/history` показывает последние расходы;
- `/stats` показывает сумму за текущий месяц;
- `/undo` удаляет последнюю запись;
- бот нормально отвечает на ошибочный ввод;
- README содержит инструкции по запуску.
